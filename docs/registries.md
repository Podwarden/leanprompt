# Listing leanprompt in skill and plugin registries

Back to the [docs](README.md).

A checklist for the maintainers. **Every step here is done by the owner, by hand, from the owner's own accounts. Nothing in this repository submits anything.** Requirements were read from each registry's documentation on 2026-11-26; they change, so read the linked page again before submitting.

## Before any of them

- [ ] The npm package is published, so `npx leanprompt install` works as the README says.
- [ ] The repository is public, the `main` branch holds the release, and its tag (`v<version>`) exists.
- [ ] `npm pack --dry-run` lists the README, NOTICE, LICENSE, LICENSE-DOCS, `cli/dist`, `skills`, `forms`, `providers`, `models` and `runtimes`, and no tests or fixtures.
- [ ] The README's "Without / With" images load from `https://github.com/Podwarden/leanprompt/raw/main/docs/assets/`.
- [ ] No `.DS_Store` or other system files are committed.

## skills.sh

skills.sh is a leaderboard of skills installed with the `skills` command line tool (`npx skills add <owner>/<repo>`), ranked by that tool's anonymous install counts; it is not a registry with a form. Sources: [skills.sh](https://skills.sh), [vercel-labs/skills](https://github.com/vercel-labs/skills), [Vercel's announcement](https://vercel.com/blog/introducing-skills).

- [ ] Layout: skills in `skills/<name>/SKILL.md`, with `name` equal to the folder name and a `description`. This repository already has that layout; `skills/_template` has no `SKILL.md` and is not a skill.
- [ ] Check what the tool finds: `npx skills add Podwarden/leanprompt --list` should list the seven skills.
- [ ] If the repository does not appear after installs, the listing is requested on the `vercel-labs/skills` issue tracker (a third-party guide says so; the official docs at [skills.sh/docs](https://www.skills.sh/docs) are the place to confirm).
- [ ] Note for the listing text: installing through `skills` copies the skill folders only; `leanprompt install` is still the way to get the OpenCode command and the `AGENTS.md` block.

## Claude Code: this repository's own marketplace (live today)

Already working: `/plugin marketplace add Podwarden/leanprompt`, then `/plugin install leanprompt@leanprompt`. Source: [code.claude.com/docs/en/plugins/publish](https://code.claude.com/docs/en/plugins/publish.md).

- [ ] `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` are generated by `npm run build:forms`; bump the version in `package.json` for every release, or users keep the old copy.
- [ ] `claude plugin validate --strict .` passes at the repository root.
- [ ] Install from a local marketplace and type `/leanprompt` in a session: it should list the commands. The skill is `/leanprompt:leanprompt`; bare `/leanprompt` runs it unless another command has that name.

## Anthropic's plugin directory (claude.ai)

One listing reaches claude.ai, Cowork and Claude Code. Submitted from the developer portal at [claude.ai/directory/manage](https://claude.ai/directory/manage) by someone on a paid claude.ai plan (Submit new, then Plugin bundle). Anthropic's official marketplace, `claude-plugins-official`, does not take submissions through the portal. Sources: [Publish and distribute a plugin](https://code.claude.com/docs/en/plugins/publish.md), [pre-submission checklist](https://claude.com/docs/plugins/pre-submission-checklist.md), [Anthropic Software Directory Policy](https://support.claude.com/en/articles/13145358-anthropic-software-directory-policy).

- [ ] Manifest: `name` (`leanprompt`: lowercase, not a reserved word), `description`, `author`, `version`, plus `homepage`, `repository` and `license`, all set by `build:forms`.
- [ ] README of at least 40 words outside code blocks in the plugin folder, and a license (the `license` field in `plugin.json`, or a `LICENSE` file).
- [ ] Decide the plugin folder. Today it is the repository root (`"source": "./"`). The checklist holds for a reviewer: a `package.json` beside `package-lock.json` in the plugin folder (Claude Code would install those packages), more than 512 files, and any file over 256 KiB that is not an image. A small `plugin/` folder holding only `.claude-plugin/plugin.json`, a README, a license and `skills/` (generated by `build:forms`) avoids all three. This is an owner decision.
- [ ] No symbolic links, submodules or Git LFS files in the plugin folder.
- [ ] An icon: a square PNG, 512 to 2048 px a side, at `.claude-plugin/icon.png` (or `icon` in `plugin.json`). `claude plugin validate` warns that there is none. The first icon saved in the portal stays the listing icon, so choose it before the first save.
- [ ] Run the portal's Validate, fix every finding marked Blocking, then submit.
- [ ] The README describes what the plugin runs, sends or fetches: the skills run no code on their own; the CLI is run by the user through `npx`; nothing is sent anywhere.

## Cursor marketplace

Cursor plugins are git repositories with a `.cursor-plugin/plugin.json` manifest (only `name` is required), with skills found in `skills/`. Submitted for manual review at [cursor.com/marketplace/publish](https://cursor.com/marketplace/publish); every plugin must be open source and every update is reviewed. Source: [cursor.com/docs/plugins](https://cursor.com/docs/plugins).

- [ ] Add a generated `.cursor-plugin/plugin.json` (`name`, `description`, `version`, `author`) to `build:forms`. Not built yet.
- [ ] Test it locally by copying the plugin to `~/.cursor/plugins/local/leanprompt` and reloading the window; type `/leanprompt`.
- [ ] Submit at cursor.com/marketplace/publish.
